# Implement 与 Test 阶段

本文件只适用于标准 SDLC。Debug 和 Script 按 `debug-script.md` 使用各自单一文档，不补建标准施工或测试文档。

## Implement：施工压测与实现

1. 校验 `001-设计文档.md` 已完成详细设计层级且机器状态无未确认项、无阻塞；运行 `start --phase implement`。
2. 使用 `assets/施工文档模板.md` 生成 `002-施工文档.md`，在同一文档中维护任务规划、Grill 决策、执行记录、文件/SQL 改动、偏差和验证结果。
3. **无论是否显式存在待确认项，都必须对施工文档执行 Grill-with-docs 压测。** 至少检查：
   - 文件范围与上下游影响；
   - 任务顺序和依赖；
   - 测试、迁移、兼容、回滚和观测遗漏；
   - 故障恢复、数据安全和独立验证能力；
   - 是否存在更小、更安全的实施路径。
4. 压测开始时运行 `review --status in_progress`。每个决定立即回写施工文档；压测完成后删除无效任务、调整顺序、补充遗漏项，先运行 `update --open-items 0`，再运行 `review --status completed --evidence [施工文档中的压测记录]`。
5. 评审机器状态完成后运行 `update --document-state ready`。只有文档达到“可施工”、`review.status=completed` 且机器状态无未确认项、无阻塞时才开始编码。越出允许文件范围前先更新并重新评审施工文档。
6. 按任务依赖施工。每个任务开始、阻塞、恢复或完成时，在 `002-施工文档.md` 同步：
   - 任务看板和执行时间线；
   - 实际操作、问题、决定及结果；
   - 文件、符号、SQL、改动意图和验证证据；
   - 计划偏差、重新评审结果和遗留项。
7. 原始工具调用和命令输出追加到 `onlyAI/operations-log.md`。它面向 AI，不能替代施工文档中的人类执行记录。
8. 使用 `task --id [任务] --status completed --evidence [证据]` 同步机器状态，再同步可信会话的 AI 登记。
9. 全部任务完成后，把施工文档标记为“已完成”，运行 `update --document-state complete --open-items 0` 和 `complete`；施工文档不能用 `final` 跳过 `ready → complete`，状态投影为 `implement / 已完成 / 75%`。

文件改动以路径和符号为主要定位信息，行号只作为最终快照。AI 新增或维护的测试代码必须放在对应项目或模块的 `ai_test/`。

## Test：用例、执行与结论

1. 校验施工文档中的任务、文件改动、偏差和验证结果完整；运行 `start --phase test`。
2. 使用 `assets/测试文档模板.md` 生成 `003-测试文档.md`，在同一文档中维护风险范围、用例、实际结果、命令证据、缺陷、汇总和结论。
3. 根据需求风险覆盖适用的正常、边界、非法输入、权限、并发、迁移和回滚场景；不为不适用维度制造空用例。
4. 执行可用的单元、集成、端到端、静态检查和构建命令。将可读结果写入测试文档，原始过程证据写入 `onlyAI/testing.md` 与 `onlyAI/verification.md`。
5. 在 `onlyAI/review-report.md` 检查改动边界、回归风险、遗漏测试和文档一致性。
6. 测试发现重大设计缺陷时回退到 Design-2；普通实现缺陷回到 Implement，在同一施工文档中追加修复执行和文件改动，再重新验证。
7. 完成测试文档结论后，使用 `test --result passed --evidence [证据]` 写入通过结论并把文档状态同步为“已完成”；有条件通过还必须使用 `--risk-accepted` 并记录用户接受的遗留风险。状态投影为 `test / 待关闭 / 95%`；失败结论把文档恢复为评审中、写入阻塞并拒绝关闭。
8. Test 不写入 `done / 100%`。分阶段模式提示用户进入 `sdlc-close`；Solo 自动执行 Close。

## 旧任务兼容

已有 `003-施工文档.md`、`003-执行记录.md`、`003-文件改动记录.md` 或分离测试文档的任务不机械覆盖历史文件。下一次修改对应阶段时，把仍有效的执行、改动、用例和结论合并到新的聚合文档，注明来源并停止双写；只读历史任务可以保留原结构。

每个阶段交付前运行状态脚本 `validate`。
