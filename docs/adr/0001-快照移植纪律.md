# 0001 · 快照移植纪律

- **状态**：已采纳
- **日期**：2026-08-29
- **来源**：`/improve-codebase-architecture` 评审候选 1，issue #58
- **适用**：本仓内一切「把上游项目整体搬进来做成插件」的移植行为

## 背景

本仓已两次做这种搬运：`sdlc` 源自 `AtlantisYuki/prompt`，`dsh-spec` 源自 deepseek-harness（参考源 `.dsh-src/`）。每次都要回答同一个问题：**上游的东西哪些能动、哪些不能动。**

此前这个答案只写在 `CONTEXT.md` 的术语条目里，而两个插件目录内**零引用**它。后果是每动一次都得靠人肉回忆或重新 diff 一遍才能判定，无法委托给 agent——这不是文档问题，是判定依据不在被判定物旁边。

本 ADR 把规范性内容从术语表收回来。`CONTEXT.md` 只保留「快照 / 重快照 / 表面适配」三个词的识别性定义，并指回这里。

## 决策

### D1 · 以提交指认快照，不以版本号

上游发版不可靠，一律以提交号指认。当前实例：`sdlc` = `AtlantisYuki/prompt@7cdfc64588a1a8eb7d338e3f6f717f1c7abcd81`（2026-07-22）。插件 README 记一行溯源（仓库、提交、日期）。

### D2 · 整体重快照，不做增量同步

上游更新入库的唯一方式，是在新提交上**整体重跑移植**：取新快照 → 重做表面适配 → 产物整体替换。不做 cherry-pick、不做增量 patch、不做「只更新某几个文件」。

触发时机：人工看到上游动静或想动这个插件时。不设固定周期。

### D3 · 表面适配是唯一允许的改动层

分三类，判定的唯一依据是「相对上游快照的字节」：

| 类别 | 定义 | 相对上游 |
|---|---|---|
| **内核** | 上游内容本体 | 字节级一致，动一个字节就要走 D2 |
| **表面适配** | 入口与接线面：技能名、路径移位、钩子接线、安装说明、插件元数据 | 允许按本仓惯例改写，改了要能说明理由 |
| **纯新增** | 上游不存在的文件：测试、README、CLAUDE.md、`.gitattributes`、plugin.json、hooks.json | 自由改，不算适配 |

#### sdlc 实例清单（2026-08-29 实测 cmp/diff 对 `7cdfc64` 得出）

**可动层**——`sdlc/tests/`、`sdlc/README.md`、`sdlc/CLAUDE.md`、`sdlc/.claude-plugin/plugin.json`、`sdlc/hooks/hooks.json`、`sdlc/hooks/cc_session_start.ps1`

**禁区**——`sdlc/skills/sdlc/` 下 21 个文件中的 19 个：

- `assets/`（8 个）
- `references/` 除 `registration.md` 外（7 个）
- `scripts/ai_register_core.py`、`scripts/task_state_core.py`、`scripts/install_codex_hook.ps1`、`scripts/install_grok_hook.ps1`

**已适配面**（2 个，落在新表中）：`skills/sdlc/SKILL.md`（技能名 + 入口清单）、`skills/sdlc/references/registration.md`（Hook 安装节）

#### D3.1 · 快照目录禁止换行符转换

`sdlc/.gitattributes` 把 `skills/sdlc/**` 标为 `-text`。

理由：本机 `core.autocrlf=true`，git 在 checkout / reset / 克隆时会把 LF 改写为 CRLF。对一个声称「与上游字节级 1:1」的目录，这等于让 git 单方面破坏快照——而且会让内核冻结守卫在干净克隆后立刻误报。`-text` 让 git 完全不碰这些字节。只作用于快照目录，可动层照常走仓库默认策略。

#### D3.2 · 内核冻结由测试执法，不靠自觉

`sdlc/tests/kernel-baseline.json` 记下 21 个文件的 sha256 与类别，`KernelFrozenTest` 比对。覆盖**整个快照目录**（含 2 个已适配面），不只守 19 个内核——否则往适配文件的内核段落里塞内容会静默通过，而那正是表面适配纪律最容易被侵蚀的地方。

守卫变红只有两种可能：有人改了快照（该还原），或刚做完重快照（该重生成基准）。`sdlc/tests/update_baseline.py` 是重生成的唯一入口。**不设自动更新**——那会让「手贱改了内核」和「刚重快照」变得无法区分，正是本守卫要防的事。

## 已知遗留

两条都在禁区里，只能等下次重快照（D2）时处理：

1. **悬空的安装路径**：`scripts/install_codex_hook.ps1` 与 `install_grok_hook.ps1` 保留了上游字节，但它们要安装的 `scripts/hooks/codex_session_start.ps1`、`grok_session_start.ps1` 在移植时已被有意丢弃，`Join-Path $skillRoot "scripts\hooks\codex_session_start.ps1"` 指向不存在的文件。目前只靠 `references/registration.md` 一句「仅随快照留存作参考，勿用」软约束。
2. **清单与目录不一致**：`skills/sdlc/SKILL.md` 的入口清单删掉了这两个文件的条目，但文件仍在目录里。

## 与 `docs/agents/domain.md` 的张力

`docs/agents/domain.md:11` 要求：「若 `CONTEXT.md` / ADR 不存在，静默继续，不要主动建议创建。」

本 ADR 是对该指令的**有意偏离**，理由：那条针对的是「文件缺失」——不要在缺失时凭空造一套纪律；此处是「已有内容放错位置」——规范性内容本就存在，只是被降级成了术语条目，藏在插件找不到的地方。把已有的决策归位，不等于新建决策。

附带修正：`domain.md:41` 宣称本仓「有根 `docs/adr/`」，而该目录此前并不存在。本 ADR 使其成真。

## 附带修正

`CONTEXT.md` 此前**未纳入版本控制**（`git ls-files` 查无、`git log -- CONTEXT.md` 为空）。一个受控的 ADR 不能指向一个不受控的术语表——指针在克隆里是断的。本 ADR 落地时一并将其 `git add`。
