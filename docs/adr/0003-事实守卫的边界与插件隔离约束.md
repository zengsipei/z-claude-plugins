# 0003 · 事实守卫的边界与插件隔离约束

- **状态**：已采纳
- **日期**：2026-08-29
- **来源**：`/improve-codebase-architecture` 二跑候选 A，issue #61
- **适用**：本仓内一切「同一事实多处声明」的收口，以及跨插件代码的组织方式
- **与 ADR-0001 / 0002 的关系**：本 ADR 是那两次收口的**一般化**——它们各自解决了一个事实，本 ADR 解决「这一类事实」以及收口时反复撞到的那条隔离约束

## 背景

一次架构评审盘出本仓「同一事实多处声明」共 **17 处**，并发现此前三次收口（#38 规则进 `RULES.md`、#58 纪律进 ADR-0001、#60 身份进 `snapshot.json`）虽然形状相同，却是三份**互不相识**的手写断言：抽取逻辑各写一遍，跑法三种，`python -m unittest discover` 从仓库根甚至一个测试都发现不了。

三次收口证明模式有效，但同时说明：模式本身没有被复用，每次都在重写。候选 A 把这个模式收成一个 module——`interface` 是一份声明清单，`implementation` 遍历清单比对。

评审中还反复撞到一条约束：**插件经市场单独安装，运行时不能跨插件共享文件**。它三次差点导致「抽个公共模块给三个插件用」这类提议。这条约束此前只存在于口头与记忆里，本 ADR 一并钉住。

## 决策

### D1 · 只守跨文件一致性

清单只登记「**一个声明处 ↔ 一处或多处副本**」这一类。两类不变量**不进清单**：

- **格式校验**——声明处自身写得对不对（例：`upstream_commit` 必须是 40 位十六进制）。它没有副本。
- **覆盖完整性**——机器产物是否覆盖了每个对象（例：基准必须覆盖快照里的每个文件）。它守的是产物，不是表述。

理由：这两类不是「同一事实的多份表述」，语义上属于另一件事。把它们塞进清单，条目会从「声明 + 副本 + 抽取方式」膨胀成「任意不变量」，interface 变宽而 implementation 退化成一个迷你测试框架——深度反而下降。它们留在原地，离被守的对象更近。

### D2 · 声明处 = 人做决定的那一侧

声明处由**对外契约或规则文档**承载，副本是**被它驱动的实现与文档**。

- feishu 事件集：声明处是 `hooks.json` 的事件键（Claude Code 实际会触发哪些事件），副本是 `renderers.RENDERERS` 的键。
- dsh-spec 枚举：声明处是 `RULES.md` 的 `§` 锚点，副本是命令面参数串与技能面描述。

`eq` 关系两侧漂移都抓得到，所以方向真正影响的是**失败信息的读法**：「契约说监听 8 个事件，实现只渲染 7 个」比反过来说更贴近人的心智。

### D3 · 清单是 interface，守卫是 implementation

`tools/consistency_facts.json` 里的一行 = 事实名 + 声明处 + 副本 + 抽取方式 + 关系。新增一个事实 = 加一行，**不改 `tools/test_consistency.py`**。

抽取是声明式的（六种 extractor、三种 relation）。保留 `custom` 逃生口，但使用时必须在该条目旁写一行注释说明理由——不写理由的逃生口等于把 implementation 漏回 interface。

`json_path` 首批只支持点分路径，不支持数组选择器。需要时再加，不为「可能会用到」的事实提前加语法。

### D4 · 铁律：守卫的任何部分失效都必须是红的

- **空抽取即失败**——声明行被删、正则失配、常量被改名，都不能静默通过。
- **清单自身写错**（`file` 路径不存在、`kind` 拼错、必填字段缺失）该条目报失败，其余条目照常跑，失败信息写明「清单条目本身有问题」。

反面教材：`feishu-notify` 的 `test_all_8_events_registered` 把期望集**硬编码在测试里**，守着一个不存在的声明处——改 `RENDERERS` 是绿的，改测试里那个集合也是绿的，等于没守。已迁至清单，声明处改为 `hooks.json`。

### D5 · 不抽跨插件共享文件

**插件经市场单独安装，运行时不能跨插件共享文件。** 三个插件各自打包、各自分发，任一插件不得在运行时引用另一插件的文件，也不得引用仓库根的共享文件。

能做的是**约定 + 守卫**：约定写在文档里，守卫钉住「三处是否都符合约定」（例：三个 `hooks.json` 的调用形）。不能做的是抽一个公共启动器 / 公共模块给三个插件用——单独安装时它不存在。

本 ADR 所说的**事实守卫本身不违反这条约束**：它是仓库开发工具，位于 `tools/`，不随任何插件分发。它守卫的是源码里的事实，不是运行时的调用。

### D6 · 统一入口必须逐目录 discover

`python -m unittest discover` 从仓库根跑得到 **0 个测试**：三个插件的测试目录都不是包，Python 3.13 的 discover 不再支持命名空间包，先插 `sys.path` 也无效。

因此 `tools/run_tests.py` 逐目录 discover（每个目录的 `top_level_dir` 指自己），默认跑四个目录，失败退出码非零。守卫文件也因此必须叫 `test_*.py` 才能被发现。

## 后果

- **正**：新增一个事实从「写一段断言」降到「加一行清单」；抽不到值时守卫变红而不是变哑；三种跑法收成一个命令。
- **负**：多一层间接——看某个事实怎么被抽取的，要去读清单而不是读测试代码。已用清单里的 `note` 字段缓解。
- **负**：`contains_all` 是子串匹配，比 `eq` 弱。这是刻意换来的——技能面的描述同时是 agent 的**触发面**，用 `eq` 约束它等于把自然语言写成参数表，会损害触发能力。

## 可复制性

清单首批登记 13 条事实（dsh-spec 6 · sdlc 6 · feishu 1）。巡检盘出的另 17 − 13 = 4 类同形状问题尚未处理，可照此模式登记：

- `marketplace.json` ↔ 各插件 `plugin.json` 的 `description` 双声明（3 个插件里 2 个已漂移，**先修后入册**，见 issue #62）
- 三个插件的 `hooks.json` 调用形三分裂（受 D5 约束，只能收成约定 + 守卫）
- sdlc 可动层清单的两份过期手写列表（`sdlc/CLAUDE.md` 与 `docs/adr/0001:52` 互相不一致，且都漏了 `snapshot.json` 与 `.gitattributes`——改指 ADR-0002 D5 的排除法即可，不必入册）
- `docs/agents/domain.md` 的插件名单与根 README 不一致（漏 sdlc、多 `_template`）
