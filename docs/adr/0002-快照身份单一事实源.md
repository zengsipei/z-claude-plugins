# 0002 · 快照身份单一事实源

- **状态**：已采纳
- **日期**：2026-08-29
- **来源**：`/improve-codebase-architecture` 二跑候选 1，issue #60
- **适用**：本仓内一切快照移植插件的「快照身份」——上游提交号与表面适配面清单
- **与 ADR-0001 的关系**：补充并勘误 ADR-0001 的 D1，**不取代** ADR-0001 整体

## 背景

一次架构评审撞出两件事：一个已经发生的错误，和产生这个错误的结构。

### 已发生的错误：提交号在传抄中被截断

`sdlc` 的上游提交号在三处权威里是同一个错值：

| 位置 | 值 | 判定 |
|---|---|---|
| ADR-0001 D1 | `7cdfc64588a1a8eb7d338e3f6f717f1c7abcd81` | 39 位，非法 |
| `tests/update_baseline.py` 的 `UPSTREAM` | 同上 | 39 位，非法 |
| `tests/kernel-baseline.json` 的 `upstream` | 同上 | 39 位，非法 |
| `sdlc/README.md:39` 溯源行 | `7cdfc64588a1a8eb7d338e3f6f717f1c7dabcd81` | 40 位，正确 |

git SHA 恒为 40 位十六进制，所以前三者都是非法值——少了一个 `d`。正确值已用 `git ls-remote https://github.com/AtlantisYuki/prompt` 核对，与远端 HEAD 一致。

值得记下的形态：**三处权威同源同错，唯一正确的那份恰好是没人管的 README。** 这不是疏忽，是「同一事实多处声明」的必然结果——错一次，同步错三处，且没有任何一处能被机器发现。

### 结构问题

ADR-0001 已经把快照纪律的规范性内容收拢到一处，但它管的是**纪律**（什么能动、什么不能动），没有管**身份**（是哪个提交、哪些文件被适配过）。身份这部分当时留在生成器常量里，再由机器基准与人类文本各自抄一份。

## 勘误

**ADR-0001 正文不改。** ADR 是已接受决策的历史文本，修改它等于篡改记录；`CONTEXT.md` 的三条术语都指向它，把更正混进正文会让「当时的决定」与「现在的更正」无法区分。

正确值以本 ADR 与 `sdlc/snapshot.json` 为准。ADR-0001 的 D1（以提交指认快照、README 记一行溯源）本身完全有效，本 ADR 只是给它装上执法器。

## 决策

### D1 · 快照身份只声明一次

唯一声明处是插件根的 `sdlc/snapshot.json`，三键 `upstream_repo` / `upstream_commit` / `adapted`。

其余各处一律是副本或产物，不声明：ADR 与 CLAUDE.md 是引用，README 溯源行是被测试钉住的副本，`kernel-baseline.json` 是机器产物。

### D2 · 生成器是消费处，不是声明处

`tests/update_baseline.py` 不再自带 `UPSTREAM` / `ADAPTED` 常量，改为读 `snapshot.json`。它只做两件事：把人工裁决（哪些文件是适配面）落到基准的 `category` 上，把字节算成 sha256。

事实源放进生成器，等于让人类为了看一眼「我们跟的是哪个上游」去读 Python 常量。

### D3 · 人类文本保持静态，由测试钉住

ADR-0001 D1 要求 README 记「仓库、提交、日期」三件套溯源。这条现在由 `tests/test_snapshot_contract.py::SnapshotIdentityTest` 执行：

- README 溯源行精确匹配，仓库与提交号逐字相等；**日期只校验格式、不校验值**——重快照时值会变，钉住值等于逼人在格式之外还要改东西。
- CLAUDE.md 允许写缩写（可读性），但必须断言为 `upstream_commit` 的前缀且 ≥7 位——既保住可读，又让缩写无法悄悄漂走。
- ADR 正文**故意不断言**。被测试钉住意味着每次重快照都得改历史记录，那不是校验，是篡改。

### D4 · 声明与产物之间加断言

- `snapshot.json.adapted` 集合 == 基准里 `category=adapted` 的文件集合
- 基准的 `upstream` == `<upstream_repo>@<upstream_commit>`
- `upstream_commit` 必须是 40 位小写十六进制

前两条防「改了声明却没重跑生成器」——`KernelFrozenTest` 只比 sha256、不比 category，这种情况会静默过期。第三条防这次的错误重演：如果当时有这条断言，第一次跑测试就会红。

### D5 · 可动层用排除法表述

`skills/sdlc/` 之外的一切都是可动层，新增文件自动属于这一层，不必登记。`skills/sdlc/` 之内的分类以基准的 `category` 为准，由 `update_baseline.py` 打印。

理由：手写清单需要持续维护，而且它当时已经漏了 `sdlc/.gitattributes`。排除法与 D3 的判据（相对上游快照的字节）同形，零维护。

### D6 · 适配面文件在快照中不存在时硬报错

保留 `update_baseline.py` 的 `SystemExit`，并把诊断信息写清楚（列缺失文件 + 两种成因）。

只有两种成因——声明写错，或上游在新提交里真删了。两种都需要人看一眼再决定；降级为警告会让它沉进输出无人过问，而适配面是快照里唯一的人工裁决，值得留这道闸。

## 后果

- **正**：重快照只改一处声明再重跑生成器；提交号非法即时变红，不再靠肉眼。
- **负**：多一个文件 `sdlc/snapshot.json`；声明与基准之间多了一道需要同步的关系——已由 D4 的两条断言钉住，不再靠自觉。

## 可复制性

这是本仓同一形状的第三次收口：#38 把 dsh-spec 的共享规则收进 `RULES.md`，#58（ADR-0001）把快照纪律从术语表收进 ADR，本次把快照身份收进 `snapshot.json`。三次的模式相同——**一个机器可读的单一声明处 + 一条把它与副本钉在一起的测试**。

同形状的问题本仓还有（市场清单与插件清单的身份双声明、三个插件各自一套 hook 调用形），可照此模式处理。
